## Endpoint behavior

### GET /api/mapping/categories

- Requires a valid JWT. Returns independently paginated existing source bridge rows and active canonical nodes, preserving IDs, hierarchy and existing mapping fields.
- `page`/`limit` default to 1/50; `category_page`/`category_limit` default to 1/100; each page size is at most 200.
- Supports exact `platform_name`, literal raw-category/subcategory `search`, `parent_id` (an ID or `root`), and `status=unmapped|all`.
- Default sources are active PENDING/UNMAPPED rows with no target. `status=all` includes existing assignments. It does not discover new labels or reintegrate unmatched business/product records.
- Separate business, business-subcategory, and product/service sections are null, with explicit unsupported capability metadata, because no approved cross-domain schema exists.

### POST /api/mapping/map-category

- Requires a Bearer JWT, an existing user, and that user's ID explicitly configured in `MAPPING_APPROVER_IDS`. Default configuration denies approval. Cookie-only approval is rejected.
- Identifies an existing source by `mapping_id` or an exact platform/raw-category/raw-subcategory tuple; accepts ONE existing `master_category_id` target, plus an optional direct `parent_category_id` assertion.
- Validates types/IDs, source identity and active status, target existence, all active ancestors, parent levels and cycles. Preserves raw text and creates no new source/taxonomy rows.
- Uses a source-row lock and commits the mapping with an actor-attributed history row in one transaction; errors roll back.
- Identical repeated approval returns `changed=false` without duplicate history. A conflicting existing human-approved mapping returns 409.
- Separate business/product association fields return 422 `unsupported_relationship`.

### POST /api/mapping/auto-map

- Requires a valid JWT. Returns bulk suggestions only; `dry_run` defaults true. Explicit `dry_run=false` returns 422 `persistence_disabled`.
- Processes eligible active PENDING/UNMAPPED source rows without an existing target; supports exact platform filtering and `after_id` keyset pagination. Default batch 25, maximum 50.
- Normalizes comparison copies using Unicode normalization, case, whitespace, punctuation and ampersand/and equivalence. Stored raw/canonical strings remain unchanged.
- Resolves database synonyms against existing active canonical targets. Otherwise uses normalized Levenshtein similarity `1 - distance/max_length`, accepting candidates at >=80%.
- Returns up to three candidates with scores and exact/synonym, fuzzy-review, ambiguous or unmatched classifications. Ties/competitors within five percentage points require review. Even high-confidence results require manual approval.
- Reconstructs valid hierarchy paths from actual parents; excludes invalid/inactive chains. No automatic persistence, status changes, history writes, taxonomy generation or overwriting of existing mappings.
- Caps the catalog at 2000 active canonical nodes and 5000 synonyms, returning an explicit capacity error instead of using an incomplete catalog. Configured aliases score the resolved target comparison; they do not imply raw-string edit similarity.

## Explicit limitations and blocked requirements

- **Business-to-product and one-to-many product/service associations are NOT implemented.** The current approved bridge schema has one target FK and no approved cross-domain association model.
- **Bulk matching suggestions work; bulk writes and automatic mapping persistence are NOT implemented.** Suggestions require explicit individual manual approval.
- The 41 tests use SQLite memory only. Production PostgreSQL/schema compatibility, actual concurrency behavior, full Flask startup and frontend integration remain unverified.
- Manual approval requires team-approved `MAPPING_APPROVER_IDS` configuration; it defaults to deny.
- Existing legacy category/master routes have weaker authorization, including global-auth bypasses. This task does not change or secure those routes; they require separate review.
- Active canonical rows have no approval/domain flag, and legacy sync may auto-create rows. They have not been certified against the approved reference taxonomy.
- Catalogs larger than 2000 active canonical nodes or 5000 synonyms require a scoped/indexed matching design; current behavior fails closed.
- No automatic source discovery, unmatched-review reintegration, taxonomy import, spelling cleanup or frontend changes are included.
